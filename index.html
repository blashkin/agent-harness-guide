Анатомия обвязки агента

Как Claude Code собирает сессию из инструкций, скиллов, хуков и MCP, сколько это стоит и как собирать свое. Пример - рабочее монорепо на Kotlin Multiplatform: команда ведет в нем общую обвязку, а каждый добавляет поверх нее свою.

Каждый лист начинается с определений новых терминов. Листы 1-10 объясняют механику: схема, спецификация и примечания с граблями. Листы 11-14 показывают, как применить ее в проекте. Листы 15-16 помогают выбрать, как работать самому.

сводкаГлавное за минуту
по всем листам
  1. Сообщение - не один запрос, а цикл. Каждый шаг заново отправляет весь контекст, но неизменное начало читается из кэша. В примере из кэша пришло 97.6% входных токенов. листы 1-2
  2. Кэш ломают смена модели, /compact, пауза дольше TTL и включение fast mode. TTL - 1 час на подписке и 5 минут по API. Смена effort на Opus 5.5, Sonnet 5.5 и Fable 5.1 кэш не ломает, на других моделях ломает. лист 2
  3. Правка CLAUDE.md посреди сессии не действует до /clear, /compact или перезапуска. листы 2-3
  4. Постоянный контекст входит в каждый запрос. Инструкции, листинг скиллов и память оплачиваются десятки раз за сессию. лист 1
  5. Claude Code и claude.ai живут раздельно. Чаты и Cowork делят память и инструкции между собой, а Claude Code не видит ни того, ни другого. Одно правило приходится класть в оба места. лист 3
  6. Скилл в контексте - это только описание. Плохое описание, и скилл не вызовется. лист 4
  7. Сабагент возвращает только отчет. Это самый дешевый способ прочитать много. лист 5
  8. Хук - единственный способ сделать что-то гарантированно, без просьбы к модели. лист 6
  9. MCP грузятся лениво, в запросе лежат только имена инструментов. CLI сервиса часто дешевле MCP. лист 7
  10. Desktop дороже CLI на 20-30k в каждом запросе, а по API-ключу Desktop не работает. листы 9, 16
  11. Главный рычаг экономии - короткие сессии. Сессия на 200+ запросов читает в 20-150 раз больше короткой. лист 13
лист1
механикаКак агент получает контекст
основа
определения
Модель
Нейросеть (Claude), которая получает текст и возвращает текст. Сама ничего не делает и ничего не хранит.
Агент
Программа вокруг модели, здесь это Claude Code. Собирает запросы, выполняет инструменты, которые просит модель, и крутит цикл до конца хода.
Запрос
Один вызов модели: весь текст отправлен разом, один ответ получен.
Контекст
Весь текст одного запроса. Его размер ограничен окном контекста.
Токен
Единица, которой модель считает текст, обычно кусок слова. В английском один токен покрывает в среднем около 4 символов, в русском меньше. Поэтому тот же текст по-русски занимает больше токенов и стоит дороже.
Окно контекста
Максимальный объем одного запроса в токенах. Все, что не влезло, модель не видит. У Opus 5.5 это 1 млн токенов. Когда сессия подходит к пределу, Claude Code сжимает переписку.

Все, что называется обвязкой, - это способы собрать текст, который уходит модели на каждом шаге. Запрос - это один вызов модели: Claude Code отправляет ей весь текст разом, модель возвращает один ответ, текст или вызов инструмента. Атомарен один запрос: текст ушел - ответ пришел. Твое сообщение не атомарно, это цикл из нескольких запросов. Модель просит инструмент, Claude Code его выполняет и отправляет новый запрос с результатом, и так, пока модель не ответит без инструментов. Каждый шаг сразу меняет файлы: если прервать ход на середине, сделанные правки останутся.

рис. 1.1 сообщение "поправь опечатку в README" - три запроса
запрос 1системный промпт, инструменты, инструкции, твое сообщение -> модель: вызвать Read для README.md
Claude Code читает файл саммодель в этом не участвует
запрос 2все из запроса 1 + вызов Read + содержимое файла -> модель: вызвать Edit
запрос 3все предыдущее + результат Edit -> модель: "Готово"
каждый следующий запрос заново включает в себя все, что было до него; модель не помнит запрос 1, его отправляют ей снова
рис. 1.2 из чего состоит стартовый запрос в монорепо, тысячи токенов
промпт 3.3
инструменты 10
инструкции и память 22.5
скиллы 10
Desktop +20-30
CLI около 60k / Desktop около 91k / медиана по сессиям примера 76k
вне запроса120k отложенных схем MCP и редких инструментов. Подгружаются, только когда нужны

Постоянный контекст - это часть запроса, которая от шага к шагу не меняется: системный промпт, инструменты, инструкции, листинг скиллов и память. Меняется только переписка.

Следствие 1Постоянный контекст входит в каждый запрос. CLAUDE.md не загружается в модель один раз на старте. Его текст заново включается в каждый запрос сессии, а запросов за сессию набираются десятки. Поэтому в постоянный контекст стоит класть только то, что нужно почти всегда.
Следствие 2Одинаковое начало не обрабатывается заново. Если начало запроса совпадает с предыдущим, оно берется из кэша. Это и делает большой постоянный контекст терпимым, пока его не ломают сменой модели, правкой начала или долгой паузой. Подробности и деньги - на листе 2.
Следствие 3Окно одно на всех. Инструкции, скиллы и переписка делят одно окно контекста с самой работой. Чем больше занимает постоянный контекст, тем раньше Claude Code сожмет переписку и тем больше подробностей из начала сессии потеряется.
проверка

Набери /context в любой сессии: увидишь те же слои для текущего момента. Сравни в начале и через час работы.

Как работаетЗапрос собирается в порядке: инструменты, системный промпт, переписка. Совпало начало - начало читается из кэша.
В монорепоКэш включен всегда. На подписке Claude Code пишет его на 1 час, на API-ключе на 5 минут. Час на API-ключе включается настройкой promptCacheTtl.
Сколько стоитOpus 5.5, цены на 24.06.2026: вход $4 за млн, выход $20, чтение кэша $0.20, запись на час $8. Чтение кэша - 61% расходов примера, запись - 30%, ответы - 9%.
Как управлятьОдна задача - одна сессия, между задачами /clear. Не менять модель и effort посреди работы. Читать много - через сабагента.

примечание

Деньги здесь - API-эквивалент. На подписке платишь фиксированно, а токены съедают лимиты плана. При оплате по API-ключу эти цифры были бы счетом.

лист3
механикаИнструкции и память
CLAUDE.md, AGENTS.md
определения
Инструкции
Постоянные правила для агента в markdown-файлах. Попадают в каждый запрос как часть постоянного контекста.
CLAUDE.md
Файл инструкций, который Claude Code находит сам: в домашней папке, в корне проекта, в каталогах выше по дереву и лениво во вложенных.
AGENTS.md
Тот же по смыслу файл, но по общему стандарту для разных агентов (Cursor, Codex и других). Claude Code читает его сам, но по умолчанию только если рядом нет CLAUDE.md и CLAUDE.local.md. Иначе его подключают строкой @AGENTS.md в CLAUDE.md или настройкой Project instructions = claude-md-and-agents-md.
Импорт
Строка @путь в файле инструкций, на место которой встает содержимое другого файла.
Память
Заметки, которые агент сам ведет между сессиями в отдельной папке. В каждый запрос попадает только их индекс MEMORY.md, сами заметки агент читает, когда они нужны.

Файлы на диске и git

/compact мягче: он заменяет переписку кратким пересказом. /clear выбрасывает ее целиком. Новая сессия равна /clear.

правило

Перед /clear или закрытием сессии попроси агента записать важное в память или в файл плана. Иначе ощущение "оторвало половину памяти" гарантировано: в памяти лежит только то, что агент успел записать.

Как работаетНа старте грузятся CLAUDE.md пользователя, проекта, CLAUDE.local.md и все CLAUDE.md выше по дереву каталогов. Вложенные подгружаются лениво, когда агент читает файл в их каталоге. @путь вставляет другой файл.
В монорепоКорневой CLAUDE.md - одна строка @AGENTS.md. AGENTS.md - правила команды. Глобальный файл - твой общий текст для чатов и кода, CLAUDE.local.md - правила только для этого репо.
Сколько стоит22.5k токенов в каждом запросе, около 1 млн прочитанных токенов на медианную сессию, $0.21 на Opus 5.5. Вложенный AGENTS.md одного модуля весит 88 KB и подгружался в 38 сессиях.
Как сделать своеКак говорить в чатах - профиль claude.ai. Как работать во всех проектах Code - ~/.claude/CLAUDE.md. Только этот репо - CLAUDE.local.md. Правило модуля - AGENTS.md в его каталоге. Факт, узнанный по ходу, - память.
проверка

Спроси агента: перечисли пути всех загруженных файлов инструкций. Модель честно называет, что видит.

лист4
механикаСкиллы и команды
SKILL.md
определения
Скилл
Именованная инструкция для конкретного случая: папка с SKILL.md и файлами рядом. В контексте постоянно висит только ее описание, тело подгружается при вызове.
Описание скилла
Одна-две фразы о том, когда его использовать. По ним модель решает, вызывать скилл или нет. Плохое описание - скилл не сработает, даже если тело хорошее.
Листинг скиллов
Список имен и описаний всех доступных скиллов. Входит в постоянный контекст каждого запроса.
Команда
Скилл, который ты вызываешь вручную: /имя. Раньше команды были отдельным механизмом, теперь это тот же скилл.
рис. 4.1 что лежит в контексте всегда, а что по вызову
листинг 10k всегдаимя + описание, 70-310 токенов на скилл, около 50 скиллов
-- вызов ->
тело SKILL.md по вызовуhumanizer-ru 16 KB, autotest 51 KB, файлы рядом
описание - условие запуска: модель выбирает скилл по нему
---
name: mr-review
description: Use when the user asks to review a GitLab MR - "глянь MR", "отревьюй !12345".
disable-model-invocation: false   # true: не висит в листинге, только /mr-review
allowed-tools: Read, Bash         # что разрешено без вопроса внутри скилла
---
# тело: шаги, правила, ссылки на файлы рядом
Как работаетСкилл - папка с SKILL.md. Вызывает его ты через /имя или модель, если описание подходит к задаче. Слэш-команды теперь тот же механизм.
В монорепо39 проектных, 8 платформенных, 3 личных, плюс плагины Desktop. Вызывались 12 проектных. Из 202 вызовов почти все сделала модель, руками набрано 6.
Сколько стоитЛистинг - 10k в каждом запросе. Тело - только при вызове. Кириллица дороже в токенах, поэтому русские описания раздувают листинг.
Как сделать своеЛичный - ~/.claude/skills/имя/SKILL.md. Для команды - исходники харнесса и MR. Для чатов - Customize, Skills.

примечание

Два скилла с похожими описаниями конкурируют, и модель выбирает сама. Скилл, который не вызывается, почти всегда страдает от описания, а не от тела.

лист5
механикаСабагенты
.claude/agents
определения
Сабагент
Отдельный агент со своим контекстом. Основной агент поручает ему часть работы и получает назад только итоговый отчет. Все, что сабагент прочитал по дороге, остается у него.
Основной агент
Агент твоей сессии. Ставит сабагенту задачу и получает от него отчет.
Отчет
Последнее сообщение сабагента. Только оно попадает в контекст основного агента.
Тип сабагента
Заготовка с промптом, набором инструментов и моделью. Бывают встроенные (Explore, general-purpose, Plan) и свои, из .claude/agents/.
рис. 5.1 отдельный контекст, наружу только отчет
основная сессиязадание: что найти и зачем
->
сабагентсвой промпт, CLAUDE.md, git status; читает 100k
->
отчет 3kв основной контекст
Как работаетИсторию твоей сессии сабагент не видит. Возвращает только итоговый отчет, все прочитанное по дороге остается у него.
В монорепоExplore 58 раз, general-purpose 51, coder из харнесса 36, code-reviewer 5.
Сколько стоитВсе сабагенты за три месяца - $167, 3.5% от общего. Дешево, потому что их сессии короткие, а основная не раздувается.
Как сделать свое~/.claude/agents/имя.md: фронтматтер name, description, tools, model, в теле промпт. Модель попроще для черновой работы - прямая экономия.
примечание

Сабагент не видит твою переписку с основным агентом. Все, о чем вы договорились, основной агент должен сам передать в задании - тексте, с которым он запускает сабагента. Если ограничение важно, прямо попроси включить его в задание.

примечание

Отчет сабагента - это вывод модели, а не проверенный факт. Ключевые утверждения из него стоит перепроверить.

лист6
механикаХуки
settings.json / hooks
определения
Хук
Скрипт, который Claude Code запускает сам, когда в сессии происходит событие. Модель в этом не участвует, поэтому хук срабатывает всегда. На вход скрипт получает описание события, в ответ может добавить текст в контекст или запретить действие.
Событие
Момент в жизни сессии, к которому можно привязать хук: старт сессии, отправка сообщения, до и после вызова инструмента, конец хода и другие.
additionalContext
Текст, который хук возвращает Claude Code, чтобы тот добавил его в контекст модели.
Шим
Файл-переходник: CLAUDE.md из одной строки @AGENTS.md рядом с AGENTS.md. Нужен, потому что при корневом CLAUDE.md Claude Code по умолчанию AGENTS.md не читает. С настройкой Project instructions = claude-md-and-agents-md шимы не нужны.
Блокирующий хук
Хук, который завершается с кодом 2 и этим запрещает действие, например вызов инструмента.
рис. 6.1 где в сессии можно повесить хук один раз за сессию

Как работаетСкрипт получает описание события в JSON: что за событие, какой инструмент, с какими параметрами. Может вернуть текст для контекста через additionalContext или запретить действие кодом выхода 2. Это единственный способ сделать что-то гарантированно, а не по просьбе к модели.
В монорепоХуки на старте сессии решают две задачи. Раскладывают шимы: рядом с каждым AGENTS.md кладут CLAUDE.md из одной строки @AGENTS.md, потому что при корневом CLAUDE.md Claude Code по умолчанию AGENTS.md не читает. Проверяют, не вышла ли новая версия командного харнесса.
Сколько стоитТокенов не тратит, платишь только за добавленный текст. Время - сколько работает скрипт: хук на старте задерживает начало сессии.
Как сделать своеСкрипт в ~/.claude/hooks/, регистрация в hooks файла настроек, ответ - JSON с hookSpecificOutput.
примечание

В auto mode агент не может сам менять собственные настройки, поэтому зарегистрировать хук приходится вручную. Это защита, а не баг.

механикаMCP

определения
MCP
Model Context Protocol - открытый протокол, по которому агент подключает внешние инструменты: трекер, GitLab, Figma и другие.
MCP-сервер
Программа, которая по этому протоколу отдает агенту набор инструментов. Работает как процесс на машине (stdio) или как удаленный адрес (http).
CLI
Программа, которой управляют текстовыми командами в терминале. У многих сервисов есть своя CLI, например glab для GitLab. Агент может вызывать ее вместо MCP-сервера.
Коннектор
MCP-сервер, подключенный в аккаунте claude.ai. В Desktop он появляется автоматически.
рис. 7.1 отложенная загрузка: в запросе только имена
в запросеимена инструментов, 0.7k
-- ToolSearch ->
gitlab 43k
Figma 33k
Gmail 24k
без отложенной загрузки это +100k в каждом запросе
инструмент
Одна операция сервера: найти задачу, создать MR, прочитать макет.
отложенная загрузка
В запросе лежат только имена инструментов. Полное описание модель подгружает через ToolSearch, когда инструмент понадобился.
Как работаетВнешний сервер с инструментами: процесс на машине (stdio) или адрес (http). Ответ MCP-инструмента ограничен 25k токенов, лимит меняется переменной MAX_MCP_OUTPUT_TOKENS. Ответ остается в переписке и входит в каждый следующий запрос, поэтому один огромный ответ съел бы окно контекста.
В монорепоMCP-серверы приходят из нескольких мест: личные в ~/.claude.json, командные в .mcp.json, из конфига Desktop и коннекторы claude.ai. Поэтому один сервер легко оказывается объявлен дважды.
Сколько стоитИмена почти бесплатны, схемы - только подгруженные. Если у сервиса есть CLI, например glab, он часто выгоднее MCP: не тратит контекст на схемы и выдает ровно нужный вывод.
Как сделать своеclaude mcp add --scope user имя -- команда для всех проектов, --scope project - в .mcp.json для команды.
Приоритет при одинаковом имениГде хранится
1. local~/.claude.json в записи проекта
2. project.mcp.json в репо, требует одобрения
3. user~/.claude.json верхнего уровня
4-5. плагины и коннекторы claude.aiплагины Claude Code и аккаунт claude.ai

Запись берется целиком из источника с высшим приоритетом, поля не сливаются. MCP из конфига Desktop не видны ни CLI, ни харнессу.

лист8
механикаНастройки и разрешения
settings*.json
определения
Настройки
JSON-файлы settings.json с уровнями от организации до пользователя. В них хранятся разрешения, хуки, переменные окружения, модель и effort. В контекст модели они не попадают, их читает сам Claude Code.
Правило разрешения
Шаблон инструмента с решением allow (выполнять молча), ask (спросить) или deny (запретить). Пример шаблона: Bash(git log *).
Режим разрешений
Как поступать с тем, что правила не покрыли: спросить человека (default), пропускать правки файлов (acceptEdits), только планировать (plan), отдать решение модели-классификатору (auto).
рис. 8.1 кто сильнее: сверху вниз
managedорганизация, пользователь не переопределит
--settingsфлаг запуска, одна сессия
.claude/settings.local.jsonличное для репозитория, в git не идет
.claude/settings.jsonобщее для команды, лежит в git
~/.claude/settings.jsonличное для всех проектов

Так решается спор за одиночный ключ вроде model. Правила разрешений не спорят: они собираются со всех уровней, и deny на любом уровне сильнее allow на любом другом.

Как работаетПравила проверяются по порядку: сначала deny, потом ask, потом allow. Первое совпадение решает. Что не совпало ни с одним правилом, решает режим разрешений: в обычном агент спросит, в auto проверит модель-классификатор.
Сколько стоитТокенов не стоит. Стоит внимания: каждое лишнее разрешение - пропущенный вопрос в момент, когда он был бы нужен.
Как сделать своеЗвездочку ставь только после подкоманды: Bash(git log *). Запись наружу (push, комментарии, переходы в трекере) держи в ask, если нет уверенности.
примечание

Свои правила добавляйте в .claude/settings.local.json в корне репозитория. Этот файл личный и в git не попадает. Правила на все проекты кладите в ~/.claude/settings.json.

лист10
механикаHarness
harness sync
определения
Харнесс
Командная обвязка агента, которая лежит в git: скиллы, команды, сабагенты, хуки, MCP и инструкции. Утилита харнесса собирает из этих исходников рабочие файлы под каждого агента.
Рантайм
То, что утилита собрала на конкретной машине. В git он не коммитится.

Инструкции, скиллы, хуки и MCP с листов 1-9 можно настроить руками, каждый у себя. Харнесс избавляет от этого: исходники обвязки лежат в git, а sync собирает из них рабочие файлы под каждого агента на каждой машине.

рис. 10.1 из чего собирается рантайм
исходники в gitконфиг, скиллы, сабагенты, команды
релиз харнессаобщие скиллы и хуки
локальный конфигроль и логин
->
harness sync
->
общий пул-> .claude .cursor .opencode .zcode
мануал харнесса
хуки и .mcp.json
Как работаетРантайм в git не коммитится, поэтому в свежем клоне и новом worktree его нет, пока не запущен sync. Скиллы можно фильтровать по ролям: разработчик, QA и другие получают разный набор. Корневой AGENTS.md пишет команда, а мануал харнесса подключается в него импортом первой строкой.
Где работаетУтилита и общие скиллы ставятся на машину, sync работает локально. Сеть нужна для обновления утилиты, телеметрии и удаленных MCP. Расход токенов зависит от того, сколько скиллов попало в листинг, а не от того, где лежит харнесс.
Сколько стоитЛистинг скиллов и инструкции харнесса входят в постоянный контекст каждого запроса. В разобранном примере это около 20k токенов, примерно половина стартовых инструкций.
Как сделать своеСкилл для команды кладите в исходники харнесса и запускайте sync. Личное в командный харнесс не кладите: для него есть ~/.claude и CLAUDE.local.md.
АльтернативаВ Claude Code штатный способ раздать обвязку - плагин: пакет из скиллов, команд, сабагентов, хуков и MCP. Он ставится из маркетплейса, а для всей команды включается записью в .claude/settings.json. Плагин - формат Anthropic, он работает в Claude Code, claude.ai и Cowork. Харнесс нужен, когда в команде агенты разных производителей.
примечание

sync может менять файлы, которые лежат в git, например при смене версии харнесса. Перед sync обновите ветку, иначе его правки смешаются с отставанием ветки.

проектСвоя обвязка поверх командной
правило
определения
Личный слой
Свои правила, скиллы и настройки поверх командной обвязки.
Переопределение
Короткое правило в CLAUDE.local.md, которое меняет командное правило только для тебя. Пишется с причиной.

Командную обвязку берешь целиком и не копируешь. Свою добавляешь поверх: коротко и только там, где команда не может или не должна.

Брать у команды

  • Правила проекта и архитектуры
  • Git-цикл: ветка, коммит, MR
  • Доменные скиллы: автотесты, дизайн-система
  • MCP, объявленный в харнессе

Держать своим

  • Как агенту с тобой разговаривать и каким стилем писать тексты
  • Переопределения командных правил, коротко и с причиной
  • Настройки своего клиента, если харнесс его не покрывает: worktree, MCP вне харнесса
  • Свои скиллы, которых нет среди командных

Где будет конфликт

  • Командная проверка после правок (тесты, линтер) против "запускаю сам"
  • Инструкции под CLI или другой клиент против твоего
  • Правила коммитов: подпись агента, язык, формат
  • Похожие скиллы, личный против командного: модель выбирает сама
правило

Не копируй командный скилл, чтобы подогнать под себя: копия разойдется с оригиналом на следующем релизе. Пиши короткое переопределение в CLAUDE.local.md с причиной. Команда добавила то же самое - удаляй свое. Если твое пригодится всем, предложи его в харнесс через MR.

обслуживание

На каждую задачу

  • Новая задача - новая сессия. Если задачи идут параллельно, у каждой свой worktree
  • Большую задачу планировать старшей моделью, план записать в файл, выполнять в новой сессии на модели попроще
  • Ветку назвать по правилам CI до первого пуша
  • Перед /clear или закрытием сессии записать важное в память или план
  • Длинную сессию закрывать, а не тянуть

После обновления основной ветки

  • Сначала обновить свою ветку, потом sync
  • Проверить установку, если у харнесса есть такая команда (doctor)
  • Новые скиллы и инструкции подхватятся в новой сессии или после /clear

Время от времени

  • /context: не вырос ли постоянный контекст
  • Листинг скиллов: нет ли дублей личного и командного
  • Память: удалить устаревшее
  • Профиль claude.ai и ~/.claude/CLAUDE.md: одинаковы ли
  • CLAUDE.local.md: не дублирует ли то, что команда уже добавила в AGENTS.md
  • Обновить CLI сервисов, которые вызывает агент
